## 二、这份评测**不能**说明什么（重要）

**这个 100% 不能当作系统能力的证据。** 原因有三条，必须说清：

### 1. 样本是自造的
80 行样本是作者按规则人为构造的（每类错误按规则设计好），**不是真实野外采集的数据**。

用自己按规则造的样本，去测自己按规则写的引擎，**必然接近 100%**——这只证明「规则代码和规则设计一致」，不证明「这套规则在真实数据上够用」。

### 2. 样本量小、类型可控
80 行、5 类错误，每类样本特征都很干净。真实野外记录会有：手写识别误差、字段串行、单位混用、方言物种名、极端值、部分填写。**这些边界情况本数据集一个都没有。**

### 3. 没有第三关的成绩
本次运行 `ai_status = no_api_key_offline_fallback`——**没有 API key，模型层自动降级，第三关和第四关没跑**。所以这份评测只代表「纯规则路径」的表现。

## 三、真正要做的对照实验（已排期）

要得出可信结论，必须做这个：

| 项 | 设计 |
|---|---|
| **样本** | 40 份含错记录（5 类错误 × 每类 8 份）+ 30 份干净表 |
| **干净表里必须包含** | 「合法但看起来像错误」的边界样本（如：枝叶重叠导致分盖度之和 >100% 但总盖度正常） |
| **三组对照** | ① 纯规则 ② 规则 + 模型 ③ 单模型 |
| **指标** | 检出率（召回）、误报率、单份耗时、每百份成本 |
| **标注方式** | 由指导教师与同学**各自独立盲标**，报标注一致性 —— 不自己标自己验 |

**这份报告出来之前，任何「准确率 XX%」的说法都不可信，包括上面那个 100%。**

## 四、复现方法

```bash
cd 02_CODE_源代码
python run_eval.py
```

输出在 `02_CODE_源代码/output/`：
- `问题清单.json` —— 每条问题的行号、字段、规则编号、级别、建议
- `metrics.json` —— 记录级与问题级 TP/FP/FN、精确率/召回率/F1
- `teacher_review.csv` —— 教师复核用
- `summary_report.csv` —— 汇总

想看模型层参与的结果，先配置 `config.json` 的模型端点并设置 `DASHSCOPE_API_KEY`，再重跑——此时 `ai_status` 会变成 `online_ok`，第三关才会真正执行。
